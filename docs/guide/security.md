# 安全设计

本章集中说明模板已内置的安全机制，供架构评审、安全评审与上线检查使用。各机制的实现细节分别在对应文档中展开，本章只描述「做了什么、为什么这样做、边界在哪」。

> 模板提供的是**可用的安全基线**，不等同于通过任何等级保护或安全认证。生产上线前仍需结合自身业务补充评估，未覆盖项见文末[后续补充方向](#后续补充方向)。

## 安全模型总览

按攻击面划分防线，每一层都默认开启、无需业务代码额外接入：

| 攻击面 | 典型风险 | 模板对策 |
| --- | --- | --- |
| 数据标识 | 自增 ID 可枚举，批量遍历越权拉数据 | UUID 主键 |
| 凭据存储 | 明文/弱哈希密码库泄漏后被彩虹表还原 | Argon2 哈希 |
| 登录入口 | 脚本撞库、密码爆破、验证码穷举 | 一次性验证码 + 登录失败锁定 |
| 会话 | 令牌长期有效、被盗后无法吊销 | 短访问令牌 + 滑动刷新 + Redis 会话强制下线 |
| 权限 | 越权访问他人数据、接口裸奔 | RBAC 三级鉴权 + 数据权限 fail-closed |
| 输入 | 参数注入、多余字段写入 | 全局 `ValidationPipe` 白名单 |
| 频率 | 接口被刷、重复提交造成脏数据 | 接口限流 + 防重复提交 |
| 来源伪造 | 伪造 `X-Forwarded-For` 绕过限流与锁定 | 只信 TCP 对端，代理头按需信任 |
| 信息泄漏 | 堆栈、原始异常回传前端 | 全局异常过滤器统一翻译 |
| 运行环境 | 容器 root 运行、镜像带入密钥 | 非 root 运行 + `.dockerignore` 排除 `.env` |
| 追溯 | 事故后无法定位操作人与时间 | 操作日志 + 登录日志 + `requestId` |

## 认证与会话

- **登录链路**：账号密码 + 图形验证码 → 校验锁定状态 → 校验验证码 → 校验密码（Argon2 比对）→ 签发令牌。
- **验证码一次性**：验证码 uuid 首次校验即作废（无论对错），杜绝在有效期内反复猜答案；登录页验证码由系统参数 `sys.account.captchaEnabled` 控制，**不要关闭**，否则锁定计数可被低成本刷满。
- **双令牌**：访问令牌 `JWT_EXPIRES_IN`（默认 1800 秒）负责日常请求；刷新令牌 `JWT_REFRESH_EXPIRES_IN`（默认 7 天）滑动续期，前端 401 时静默换新并重放原请求。
- **服务端会话**：令牌状态存于 Redis，因此「签发即生效、删除即失效」，支持在线用户查看与强制下线；仅靠 JWT 自校验无法做到的即时吊销由此补齐。
- **公开接口显式声明**：默认全站需要登录，登录、验证码、健康探针等必须显式标注 `@Public()`，不会因新增 Controller 而意外裸奔。
- **前端存储约定**：`accessToken` / `refreshToken` 由 `StorageCache` 不透明持久化在 `localStorage`，不设客户端 TTL，有效性完全由服务端裁决；登出或最终 401 时成对清除。

参见 [项目介绍 · 认证机制](./project#认证机制)、[本地缓存](./storage-cache)。

## 密码与凭据

- **Argon2 哈希**：密码只存哈希不存明文，算法自带随机盐与内存困难特性，显著抬高离线爆破成本；密码字段不参与任何接口回显，编辑用户时不回传原密码。
- **初始密码与重置**：新建用户与重置密码的初始值来自系统参数，管理员可在线调整；默认演示账号 `admin / 123456` **仅用于本地体验**。
- **密钥管理**：`JWT_SECRET` 示例值为占位符，生产环境必须替换为强随机值；数据库、Redis 口令同样通过环境变量注入，不写入代码与仓库。
- **镜像不带密钥**：`.dockerignore` 排除全部 `.env`，镜像内只有生产依赖与构建产物，运行时配置由 `--env-file` 注入。

参见 [生产部署](./deployment#_2-准备运行时环境变量)。

## 授权与数据范围

| 粒度 | 实现 | 说明 |
| --- | --- | --- |
| 菜单 | 后端按角色返回菜单树，前端动态挂载路由 | 无权限的页面不会注册进路由表 |
| 按钮 | 前端 `v-permissions` / `v-roles` 指令 | 仅做展示层收敛，不作为安全边界 |
| 接口 | 后端 `@RequirePermissions` / `@RequireRoles` 守卫 | **真正的边界**，前端绕过无效 |
| 数据 | `@DataScope` + `@DataScopeSql()` | 控制能看 / 能改哪些部门的数据 |

数据权限的几个安全设计点：

- **写操作同样受控**：详情、修改、删除都会按目标数据校验范围，不因「列表已过滤」而放行直接调用的 id。
- **fail-closed**：角色、数据范围、部门缓存任一缺失或计算异常，条件退化为 `1 = 0`，宁可查空也不放行全量。
- **参数化防注入**：过滤条件全部走 QueryBuilder 占位符，不拼接字面值。
- **不泄漏存在性**：越界访问统一提示「数据不存在或无权访问」，不暴露目标数据是否存在。

参见 [数据权限](./data-scope)、[增删改查](./crud)。

## 接口与输入防护

- **参数验证**：全局 `ValidationPipe` 开启 `whitelist: true`，DTO 未声明的字段被自动剥离，阻断属性注入；前端表单校验只负责即时提示，后端 DTO 是最终防线。
- **接口限流**：`ThrottlerLimitGuard` 位于守卫链第一环，登录前即生效，按「IP + 接口」10 秒 10 次计数，超限拉黑 60 秒；验证码、分片上传等高频接口用 `@SkipThrottle()` 显式豁免。
- **防重复提交**：`@RepeatSubmit` 以「方法 + 路径 + 请求内容指纹」为键做短期窗口去重，登录等写接口默认受保护，避免连点与重放制造脏数据。
- **异常信息收敛**：所有异常经全局过滤器翻译为友好提示，原始堆栈只进服务端日志，不回传前端；每条响应携带 `requestId`，便于把用户反馈与服务端日志对齐。
- **真实 IP 识别**：`getRequestIp` 只在 TCP 对端属于可信代理时才采信 `X-Forwarded-For` / `X-Real-IP`，公网直连伪造请求头无效，限流与锁定计数不可绕过。
- **演示模式**：对外演示时开启 `SERVER_IS_DEMO`，全部非 GET 请求一律驳回，只留登录/登出白名单，访客可浏览不可改动。

参见 [参数验证](./validation)、[接口限流](./throttle)、[防重复提交](./repeat-submit)、[异常处理](./exception)、[登录失败锁定](./login-lock)、[演示模式](./demo)。

## 暴力破解防护

登录失败锁定按「账号 + IP」维度计数，是独立于接口限流的第二道防线：

| 项 | 默认值 | 可调方式 |
| --- | --- | --- |
| 失败阈值 | 5 次 | 系统参数 `sys.account.maxFailCount` |
| 锁定时长 | 1800 秒（滑动窗口） | 系统参数 `sys.account.lockSeconds` |
| 解锁 | 到期自动 / 登录成功清零 / 管理员手动 | 「系统监控 → 登录锁定」 |

设计要点：失败只累加到攻击者自己的来源 IP，无法把他人正常登录锁死；锁定期内请求在校验验证码与密码之前即被驳回，不消耗验证码；计数用 Redis `INCR` 原子自增，高并发下不丢计数。

参见 [登录失败锁定](./login-lock)。

## 数据与主键

- **UUID 主键**：业务表默认使用 UUID 作为主键，ID 无序、不可推测，无法通过自增规律估算数据量或遍历接口批量爬取；若新项目确需 `int` 自增主键，可在空库阶段用脚本一次性转换，见 [FAQ](./faq#如何把主键从-uuid-切换为-int)。
- **表结构受控**：`MYSQL_SYNCHRONIZE` 生产保持 `false`，结构变更统一走 TypeORM 迁移，避免实体同步误删字段；`init-db.mjs` 检测到目标库已有表会直接中止。
- **上传文件**：文件按 `{sha256}{扩展名}` 落盘，内容相同即同一路径，秒传与去重基于内容哈希，不存在同名覆盖他文件的路径；文件删除按引用计数执行，避免误删被多条记录共享的实体。
- **日志与上传目录**：容器内以命名卷持久化 `/app/logs` 与 `/app/uploads`，与镜像生命周期解耦。

## 审计与可追溯

| 日志 | 覆盖范围 | 关键字段 |
| --- | --- | --- |
| 操作日志 | 标注 `@Operlog` 的全部写接口，成功与失败都记录 | 操作人、模块、类型、请求参数、耗时、IP 归属地、结果 |
| 登录日志 | 登录成功与失败全量记录 | 账号、来源 IP、浏览器 / 系统、结果、提示信息 |
| 异常日志 | 全局过滤器捕获的全部异常 | 请求方法、路径、`requestId`、完整堆栈 |

- 日志落库异步执行，写日志失败不影响业务响应。
- 每条响应与日志携带同一 `requestId`，可将前端报错、服务端异常、操作记录串成一条链路。
- 登录锁定事件天然体现在登录日志中，管理员解锁动作以 `UNLOCK` 操作类型留痕，无需额外建表。

参见 [系统日志](./system-log)。

## 运行与部署安全

- **非 root 运行**：镜像以 `node`（uid 1000）运行，工作目录 `/app`，入口 `node main.js`（exec 形式，可收 `SIGTERM` 优雅退出）。
- **最小镜像**：多阶段构建，运行镜像只含生产依赖与构建产物，不含源码与 TypeORM CLI，初始化必须在开发机或 CI 完成。
- **安全响应头**：`main.ts` 启用 Helmet，统一注入安全响应头，收敛点击劫持、MIME 嗅探等浏览器侧风险。
- **健康探针**：`/live`、`/ready` 为 `@Public()` 且不依赖 DB / Redis，避免依赖抖动误判并把服务摘除。
- **反向代理真实 IP**：Nginx 必须用覆盖式写法传 `X-Real-IP` / `X-Forwarded-For`（`$remote_addr`），既不能用透传式（可被伪造），也不能缺配（所有用户共享代理 IP，限流与锁定集体误伤）。
- **传输层**：生产建议全站 HTTPS，并由 Nginx 统一跳转；同源部署时前端与接口同域名，便于收敛 CORS 与 Cookie 作用域。
- **演示环境隔离**：对外演示站开启 `SERVER_IS_DEMO=true`，并避免使用真实业务数据。

参见 [生产部署](./deployment)、[登录失败锁定 · 部署与真实 IP](./login-lock#部署与真实-ip)。

## 上线安全清单

| # | 检查项 | 要求 |
| --- | --- | --- |
| 1 | 默认账号 | 修改 `admin` 默认密码；删除或禁用不需要的体验账号 |
| 2 | `JWT_SECRET` | 替换为强随机值，且不与其它环境复用 |
| 3 | 数据库 / Redis | 使用独立强口令，端口不对公网开放，Redis 禁止无密码暴露 |
| 4 | 表结构 | `MYSQL_SYNCHRONIZE=false`，变更走迁移 |
| 5 | 验证码 | `sys.account.captchaEnabled` 保持开启 |
| 6 | 锁定与限流 | 按业务调整阈值，确认参数已生效 |
| 7 | Nginx | 覆盖式传递真实 IP，配置 HTTPS 与请求体大小限制 |
| 8 | 演示模式 | 生产环境 `SERVER_IS_DEMO=false` |
| 9 | 日志留存 | 确认 `/app/logs` 卷已挂载，日志有备份与清理策略 |
| 10 | 上传目录 | 确认 `/app/uploads` 卷已挂载且有备份策略 |

## 后续补充方向

以下为模板尚未内置、后续将逐步补充的安全方案，评审时可作为改进项跟踪：

- 敏感字段的落库加密与接口脱敏策略
- 登录二次验证（短信 / TOTP）与高风险操作二次确认
- 令牌存储方式评估（httpOnly Cookie + CSRF 防护的可选实现）
- 密码强度与定期更换策略、历史密码校验
- 上传文件的类型 / 大小 / 内容校验与隔离存储
- 依赖漏洞扫描、镜像扫描与 SBOM 产出
- 安全响应头与 CSP 的细化配置
- 审计日志留存周期与防篡改
